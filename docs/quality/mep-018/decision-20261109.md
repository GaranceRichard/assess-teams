## Écart bloquant D01 — chronologie du README

Le rapport initial explique que le remplacement tenté avant développement n'a pas modifié le texte
(ancre/encodage), puis que le gate a détecté l'absence et que le README a été corrigé.
La remise en cohérence du contenu est acquise dans P1 ; **l'ordre chronologique n'est pas réparé**.
P3 conserve explicitement cette réserve, sans résolution ni décision l'acceptant comme non bloquante.

La DoD exige : « `README.md` a été mis à jour avant le début du travail » et conclut qu'une case
applicable non cochée empêche Done. Les règles agents et la charte disent aussi qu'une correction
a posteriori ne satisfait pas cette obligation. Aucune nouvelle mention README ni campagne de tests
ne peut prouver rétroactivement ce préalable ; aucun développement n'est rouvert pour le simuler.

Condition de réévaluation : preuve contemporaine vérifiable contredisant le constat initial, ou
décision explicite de gouvernance traitant cet écart historique et son effet sur la DoD.
Aucune de ces pièces n'est fournie par les références examinées ; aucune dérogation n'est créée ici.
