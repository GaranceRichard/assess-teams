# MEP-058 — Qualification des ressources frontend

## Préparation du changement — 2026-11-15

- Périmètre : contrôler l'artefact frontend et les ressources locales, sans modifier les gates existants ni prétendre qualifier une installation MESS.
- Objectif : démontrer la présence des assets, l'identité du produit et le fonctionnement sans requête Internet avec des refus sur des copies altérées.
- Effets attendus : disposer de contrôles exécutables et de preuves par critère, liés aux octets préparés et aux entrées exactes.
- Risques : ne pas confondre serveur de qualification avec serveur cible, ni les requêtes API locales nécessaires avec une dépendance CDN.
- Vérification : vérifier empreintes et complétude, refuser démo, asset supprimé ou altéré, puis charger application et Swagger dans Chromium sans réseau externe.
- Fichier : `scripts/distribution/verify.mjs`
- Fichier : `scripts/distribution/verify.test.mjs`
- Fichier : `scripts/distribution/offline-test.mjs`
- Fichier : `scripts/quality/impact-locations.mjs`
- Fichier : `scripts/quality/tests/impact.test.mjs`

Les neuf tables Swagger MEP-057 deviennent des entrées explicites de préparation : leurs modifications
doivent perdre l'exemption « prose seule », pour ne pas réutiliser une preuve ignorant ces entrées.
Un contrôle de classification vérifiera leur élargissement sans toucher aux autres documents d'exploitation.

Le contrôle complète les gates du dépôt. Il ne les remplace pas et n'ajoute aucun circuit de publication.
Les résultats, limites et preuves par critère seront consignés dans le domaine exploitation.

## Contrôles du sous-artefact

Les dix tests de vérification sur l'artefact réel et ses copies altérées passent ; trois tests backend
couvrent le rendu local, son refus de mutation et le schéma contrôlé. Chromium charge 26 URL locales
sans requête externe ni erreur JavaScript. Les preuves et empreintes sont dans le dossier propriétaire.
La campagne exhaustive interrompue à 46 % du backend n'est pas une preuve de réussite ; aucune preuve
backend/frontend/E2E complète n'a été produite par cette tentative. Le pré-push doit rejouer ces contrôles.
Le blocage local de npm.ps1 a été résolu par la politique limitée au processus, sans modification de gate.
Le rapport de livraison et les journaux conservés avec l'artefact attestent les résultats de publication.

Le 2026-11-16, backend complet : 1 607 tests réussis, couverture 97,53 % ; frontend complet :
499 tests réussis, couvertures statements 94,97 %, branches 93,55 %, fonctions 96,47 %, lignes 95,81 %.
Le lint, le formatage, les migrations, le typage et le build sont conformes.
Le lancement E2E du backend a été refusé en sandbox lors de l'installation des hooks Git partagés :
aucun succès des parcours applicatifs n'est déduit des dix cas de démo affichés. Le lanceur bloqué a été
arrêté uniquement dans ce worktree ; le pré-push doit compléter ces parcours avec les droits de bootstrap requis.

La relance E2E autorisée du 2026-11-16 a démarré le backend réel : 155 parcours applicatifs
réussis en 23 minutes, puis dix parcours de démo réussis en 39,1 secondes. Le scope E2E complet
est conforme et sa preuve liée aux entrées exactes est enregistrée ; aucun parcours n'a été exclu.
Les dix contrôles de l'artefact et la sonde Chromium sans Internet sont également rejoués après
resynchronisation, avec le même payload de 198 fichiers. La publication et la CI indépendante
du SHA exact restent les conditions du verdict final de livraison.
