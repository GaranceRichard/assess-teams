# MEP-059 — Contrôle durable du wheelhouse

## Préparation du changement — intégration des contrôles

- Périmètre : ajouter au gate repository existant les contrôles du wheelhouse versionné et leurs vrais refus, sans modifier la sélection des scopes ni le circuit de publication.
- Objectif : faire revérifier les archives livrées par le pré-push et la CI indépendante du SHA exact, au lieu de dépendre exclusivement d’un compte rendu local.
- Effets attendus : bloquer une wheel absente, altérée ou incompatible, une transitive incohérente, un verrou divergent ou une notice retirée pendant les tests de dépôt.
- Risques : distinguer les contrôles de métadonnées multiplateformes de la sonde d’installation Windows cp313 ; ne pas télécharger de runtime de qualification dans la CI ni accepter I01 implicitement.
- Vérification : exécuter le même unittest depuis le gate repository local et distant ; la véritable installation isolée Windows et ses limites sont consignées dans le document propriétaire d’exploitation.
- Fichier : `scripts/quality.ps1`
- Fichier : `scripts/quality/tests/scopes.tests.ps1`

Le test existant de scopes doit reconnaître le nouveau contrôle repository et vérifier que son échec
bloque le gate. Son premier passage signale précisément cette nouvelle commande non encore attendue.

Le poste de préparation doit fournir pip, dont le packaging vendored lit les marqueurs et tags.
Aucune bibliothèque de préparation ne rejoint les quinze wheels cible.
Les contrôles ne changent aucune exigence qualité et ne qualifient pas un runtime de distribution.
