## Raffinement proposé — A à G

### A. Problème utilisateur

Une mise à jour peut rendre indisponibles application ou données sans parcours contrôlé livré.

### B. Valeur observable

Mettre à jour le produit en préservant la configuration, les données et une reprise possible. La conformité se constate avec les scénarios ci-dessous ; elle ne se déduit pas de l’intitulé.

### C. Périmètre exact

- **À livrer ou qualifier :** Upgrade versionné qui préserve configuration/persistance et s’arrête sûrement à tout échec.
- **Déjà présent :** Versions Git et migrations existent ; aucun upgrade MESS orchestré.
- **À conserver :** SQLite permanente, hors Internet, sans Docker/Node/npm sur cible, secrets hors sources/package, données et contrats métier existants.
- **Exclus :** Modification des règles métier, choix d’infrastructure non approuvé, qualification cible ou GO anticipés.
- **Rôles et données :** Exploitant MESS et contributeur autorisés ; composants, configuration et données du profil approuvé.

### D. Acceptation observable

1. GIVEN version installée compatible et sauvegarde vérifiée WHEN package intègre est appliqué THEN application/configuration/données SHOULD BE cohérentes à la nouvelle version.
2. GIVEN configuration locale et base persistante de N WHEN le package compatible N+1 est appliqué THEN ces données SHOULD BE conservées, migrations réellement appliquées et version/schéma installés identifiables après redémarrage.

### E. Vrai refus ou non-conformité

3. GIVEN migration échouée, package incompatible ou sauvegarde non validée WHEN upgrade est tenté THEN aucun faux succès SHOULD BE annoncé et état récupérable SHOULD BE diagnostiqué.

Le refus doit être observé, avec absence d’effet non autorisé ; une erreur inattendue ne vaut pas un refus conforme.
Les refus additionnels de la source restent applicables. En l’absence d’arbitrage, ces scénarios conditionnels
sont des propositions à finaliser, pas une règle métier adoptée ni une fiche prête par simple présence de Gherkin.

### F. Preuves attendues

Intégration version N→N+1, panne entre étapes, configuration/données avant/après ; preuve sauvegarde et arrêt ; smoke HTTP, pas de nouveau contrat métier.

Comparer attendu/observé par scénario et variante : SHA/entrées, rôle/jeu, état initial, action, résultat,
preuve et verdict. Les mesures UX reprennent [UX-01 à UX-09](../../../../../docs/quality/ux-acceptance.md) ;
aucun seuil esthétique, RPO/RTO, disponibilité ou capacité MESS supplémentaire n’est inventé.
Un test automatisé ne remplace pas la relecture visuelle ; un rapport local ne vaut pas un PV cible.
